## Live derivation

The working representation was earned through successive concrete failures.

### 1. Interface actions were not the task

G0/G1 transition/action scoring repeatedly failed.

Live click census showed:

- bottom solid/hollow tokens had causal effects;
- work slots became editable only after token selection;
- ACTION5 behaved as evaluation/status rather than structural construction.

### 2. Visible routine grammar

The frame contains:

- colored rectangular routine frames;
- tiny red unfilled variable slots;
- a top target sequence;
- bottom palette tokens.

A routine's contents are read in visual order.

### 3. Typed tokens

A controlled level-3 experiment established:

- **solid 4×4 token** written into a slot → solid literal value;
- **hollow 4×4 token** matching a routine color → hollow call symbol.

Thus:

```text
solid token  -> emit literal color
hollow token -> call/expand routine
red slot     -> variable accepting either token type
```

### 4. Fixed literals

A routine can already contain a solid token. Its output belongs to the target even when no corresponding palette token exists.

Therefore target extraction must be independent of palette availability.

### 5. Token multiplicity

Level 4 exposed duplicate physical tokens of the same semantic color/type.

The first implementation incorrectly modeled:

```text
(type, color) -> reusable coordinate
```

The corrected model is:

```text
(type, color) -> multiset of consumable token instances
```

Each visible token instance is used at most once.

### 6. Recursive synthesis

Assignments are solved as a constraint problem:

```text
expand(root program under shared slot assignments) == target sequence
```

A variable slot may choose:

- a literal whose color matches the next target symbol; or
- a visible callable routine whose recursive expansion matches the next target subsequence.

Physical palette multiplicity constrains admissible assignments.

### 7. Cyclic programs

The final level displayed two identical target rows.

That was treated as explicit periodic evidence.

The solver permits recursion only when the recursive transition consumes target symbols. Re-entry into the same routine at the same target position is rejected as a zero-progress cycle.

This admitted a mutually recursive program:

```text
routine A -> literals -> call B
routine B -> literals -> call A
```

whose finite observed expansion matched the repeated target rows.
