## Characterized mechanic

Public metadata describes SB26 as:

```text
Program synthesis:
click to fill subroutine slots
so the flattened call tree
equals a target color sequence.
```

This is not primarily a navigation task.

The visual interface is encoding a symbolic program-construction problem.

## Failure boundary

Earlier work reports that verified transition/code models could be synthesized with near-perfect fidelity on SB26 and that planning/controllability worked at high fidelity.

Yet solving remained near zero.

The stated bottleneck was **goal inference**.

That means:

```text
accurate transition model
+
ability to control the modeled system
≠
understanding what program must be synthesized
```

## Direct lesson

SB26 adds a seventh hard-case class:

```text
correct dynamics representation
≠
correct task representation
```

If the solver sees only:

```text
click slot
→ color/object changes
```

it can perfectly model the interface and still miss that the latent task is:

```text
infer compositional call structure
→ choose subroutine contents
→ flatten execution
→ match target sequence
```

So Solve the Whole Thing cannot assume every game is best represented spatially.

The solver must be willing to switch representational domain when the evidence supports it:

- spatial navigation;
- temporal procedure;
- symbolic sequence;
- program/call graph;
- object rearrangement;
- synchronization;
- other latent structures.

This is not permission to invent arbitrary abstractions. The representation must be earned from observed regularities.
