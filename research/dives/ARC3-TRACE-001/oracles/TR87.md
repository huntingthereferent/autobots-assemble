## Direct lesson

TR87 adds a tenth hard-case class:

```text
directional controls
≠
spatial task
```

The low-level affordance may be "move up/down/left/right", while the latent operation is:

- select/edit a glyph position;
- transform an output string;
- manipulate a rewrite rule;
- satisfy a symbolic relation.

So action semantics and problem semantics must remain separate.

The solver should ask:

```text
what abstract variable is this directional action changing?
```

not automatically:

```text
where is the avatar moving?
```

## Comparison with SB26

SB26:

```text
construct a program whose flattened call tree matches a target sequence
```

TR87:

```text
transform symbolic glyph strings / rewrite rules
```

Both require leaving a purely spatial representation, but they are different symbolic tasks.

That means "switch to symbolic mode" is still too coarse; the actual algebra/structure must be inferred.
