## Why LF52 matters

LF52 was the last public wall.

The project's own presentation describes the successful shape as:

```text
keep notes
→ build a proven copy of the level
→ search that copy offline at full scale
→ execute the proven winning chain
```

This is materially different from:

```text
keep trying actions until something works
```

and also different from:

```text
learn one local mechanic
→ assume the puzzle is understood
```

## Earlier failure boundary

Prior attempts were deliberately rerouted toward topology/reachability hypotheses because agents had plateaued.

Suggested questions included:

- which regions are reachable;
- which pockets are sealed;
- whether an action opens a barrier elsewhere;
- whether an object must be routed through a one-way conduit;
- whether an apparently unreachable goal implies a non-obvious gate.

The successful solve ultimately required enough persistent state/model information to support deep offline search.

## Direct lesson for Solve the Whole Thing

BP35 says:

```text
nearly-complete mechanic model
≠
procedural win
```

LF52 says:

```text
correct local reasoning
+ insufficient search horizon
≠
whole-game solve
```

Together they give two separate failure classes:

1. **missing procedure**
2. **insufficient depth / reachable-state search**

That distinction should guide live solving later.
