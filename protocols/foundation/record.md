# Protocol — Foundation Record

## Protocol ID

`foundation.record`

## Purpose

Project a completed or materially advanced work movement into the cross-lane Foundation without changing the work's original goal lane.

## Admission

A Foundation record requires:

- identifiable source work;
- current referent/problem;
- goal lane;
- field/domain labels;
- realization layer actually reached;
- evidence supporting that layer;
- provenance back to the source work.

A work item does not need to be “finished forever.” It does need enough evidence for the specific capability being recorded.

## Preserve

- source lane and source record;
- field-specific witness conditions;
- artifacts/results;
- tests/measurements/inspection;
- failures and corrections when material;
- external review/acceptance state;
- uncertainty;
- realization-layer boundary.

## Do not

- turn implementation into validation;
- turn simulation into physical evidence;
- turn a built object into a measured/inspected one without evidence;
- turn self-review into independent review;
- treat payment as proof of technical correctness;
- treat an open-source merge as proof of unrelated physical capability;
- collapse unlike domains merely to make a stronger credibility claim.

## Output

A Foundation record should make recoverable:

- work ID / source location;
- short title;
- goal lane;
- fields;
- problem/constraint summary;
- realization layer reached;
- evidence depth;
- demonstrated capability;
- difficulty evidence;
- external witness state;
- provenance;
- unresolved limits.

## Closure

The Foundation record is valid input to later read-only lenses. New evidence can deepen the record only through a new witnessed movement.
