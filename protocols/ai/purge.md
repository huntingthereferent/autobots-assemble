# AI Protocol — PURGE

## Purpose

Keep the repository small, current, and evidentially useful without deleting by assumption.

PURGE is a neutral review protocol. Age alone is not a reason to remove something, and prior usefulness alone is not a reason to keep it.

## Retention test

For any candidate, compare its present retention value against its cost and replaceability.

Prefer removal when the item is:

- obsolete, redundant, duplicated, superseded, misplaced, or generated noise;
- an old opportunity/work wrapper with no unique external outcome;
- weaker evidence for a capability that already has a stronger canonical witness;
- evidence that can now be reproduced more directly, cheaply, or clearly than maintaining the old artifact;
- a blocked/queued record whose missing external referent means it never became unique evidence.

Prefer retention when the item preserves something that cannot be cheaply recreated, including:

- payment, acceptance, submission, client feedback, external review, or another irreversible external event;
- a unique failure/counterexample needed by current work;
- a benchmark/result whose reproduction is materially expensive or uncertain;
- provenance required to interpret a retained canonical witness.

A capability does not require every historical witness. Prefer the smallest set of strongest current witnesses.

## Movement

When PURGE is invoked:

1. scan the current repository state neutrally;
2. identify a candidate or coherent redundant set;
3. compare unique retained value against reproducibility/replacement cost;
4. state what would be lost and what current witness/system replaces it;
5. obtain explicit KEEP or REMOVE authority unless the user has already explicitly authorized purging that identified class/set;
6. apply only the authorized scope;
7. repair indexes, generated views, evidence maps, and references so no deleted artifact remains authoritative.

## Job records

Job records are active/external-opportunity state, not permanent capability storage.

When an unsubmitted/unpaid job is no longer active and its technical capability is reproducible by the current system, the job wrapper is normally removable.

Keep a historical job when it contains a unique external outcome or non-reproducible evidence. Move reusable technical proof into Foundation/current project evidence rather than retaining a stale opportunity solely to support a capability claim.

## Constraints

- silence is not authorization;
- uncertainty preserves the item;
- do not strengthen a capability claim when deleting its supporting witness;
- if the last valid witness is removed, downgrade the capability until a current witness exists;
- delete dependent projections/references with the source rather than leaving stale links.

PURGE governs removals/review only. It does not authorize unrelated repository additions.
