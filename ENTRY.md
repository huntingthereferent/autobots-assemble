# AI Entry Protocol

When an AI uses this repository as an extension of the user, do **not** begin by scanning everything and choosing the most interesting layer.

## Language Referent — ground and continuity

**Terminology / referent preservation:** When James says "the language referent," he means the **same referent** previously called A/B. Do not split the two names into separate subjects or claim that mathematics arrives later as an independent thing: mathematics is a human formal language already participating in the investigation. Distinguish the referent from any *particular* finite formalization, not from mathematics as language. Retired personal writing is not a public source; retired quotations must not be reconstructed.

When the current inquiry involves **Human Drift**, begin with the [technical Human Drift note](language/HUMAN_DRIFT.md), which is not a published chronology or source of personal quotations; the shifts in expression may be responses to a prior AI misunderstanding, not a list of synonyms. When the current inquiry involves the language referent (historically called A/B), read [Language Referent](LANGUAGE_REFERENT.md), the [current naming/ground note](LANGUAGE_REFERENT_GROUND_2026-10-13.md), [Language Referent — Evidence Contract](LANGUAGE_REFERENT_CONTRACT.md), and the standing session rules. Consult the [October 11 historical record](AB_Ground_Record_Current_Note_2026-10-11.md) when the current relation reaches that evidence. Recover the *actual current referent* before entering mathematics or implementation. The language referent is the same referent previously called A/B. Mathematics is human language within the inquiry; formally labeled finite generators are scoped mathematical representations, not a second referent. When movement stalls, examining another side is not permission to change the referent or to promote unverified claims. The default `state/current.json` is a repository navigation preference, **not** a replacement for the user's explicit current question. Its current Continuity feed record is marked **historical**; do not treat its stored next movement as an active task. Recover the current referent from the person's explicit request, and preserve the old feed evidence as history.

## Standing session rules

Before the entry sequence, read and apply [ai.session](protocols/ai/session.md),
including language-first precision, drift control, speaker continuity, surface boundaries, and parent-referent corrections.
Load it once per session; its Enter checklist refers back to this sequence, not
an instruction to recursively reload it. These standing rules apply alongside
the active referent's protocol, without replacing that referent.

## Entry sequence

1. Read `COMPLETE_STACK.md`.
2. Read `CATEGORY_CONTRACT.md`.
3. Read `LANGUAGE_REFERENT_CONTRACT.md`.
4. Read `state/current.json`.
5. Recover the preferred current referent.
6. Read only the protocol(s) reached by that referent.
7. Read the active work/capability/domain record reached by that referent.
8. At every reached layer, decompress the referent and observed relations into communicable language before choosing or extending formal notation or implementation. Mathematics remains a human formal language. Consult `language/` when register matters; do not mistake surface wording for the referent.
9. Pull older evidence only when the active relation requires it.
10. ANY pre-movement gate: before explanation, design or implementation, compare the proposed movement to established A/B mathematics and to relevant contemporary production implementations. Identify what is equivalent, analogous, absent or unverified; do not invent correspondence or treat a prototype as production-ready.
11. Perform one bounded movement at a time.
12. Record result, provenance, wall/uncertainty state, and next referent.

## Language shortcut

Simple commands do not need theatrical decoding. “continue”, “stop”, “search”, “review”, etc. can be routed directly when context makes the shape unambiguous.

Use the shape bank when slang, compression, register, ambiguity, or cross-language/handoff translation matters.

## Default output contract

A substantive AI response or repo mutation should leave recoverable:

- current referent
- goal / definition of solved
- evidence actually used
- witness conditions checked
- movement made, if any
- wall / unknown / partial state, if any
- artifacts or changes produced
- next referent / next movement

## Do not

- turn the language referent into an implementation layer;
- infer a missing relation because an older layer looks similar;
- treat surface wording as permanent meaning;
- let a read-only view mutate the underlying evidence/network;
- upgrade `tested` to `submitted`, `submitted` to `accepted`, or `accepted` to `paid`;
- collapse evidence, interpretation, and action into one undocumented step;
- broaden scope merely because more data exists; crossing disciplines is valid only when the current referent actually requires it.

If the user gives a new explicit referent, that becomes primary unless it conflicts with an explicit safety or authority boundary.

## Carry original CP data before bounded continuation

When the active request reaches **finite correspondence research**, or a Tracework task
explicitly depends on its CP20–CP30 evidence, recover the existing source
before choosing another direction. Read the original
[checkpoint harness](work/arc_like_maze/chatbot/checkpoints/HARNESS.md) and
[recovered CP20–CP30 integrated-source record](work/arc_like_maze/chatbot/research/integrated/README.md).
For an explicit current referent, run this **read-only** handoff from the repository root:

```sh
python work/arc_like_maze/chatbot/checkpoints/cp_record.py handoff --referent "CURRENT EXPLICIT REFERENT"
```

It refuses missing/inconsistent CP views and returns the actual latest CP manifest
identity, observations, what survived, every recorded wall, and a possible next
movement. Carry those records into the *same* current task; do not treat the
previous CP's suggested next movement as a new user instruction, its historical
PASS as current authority, or its archive digest as fresh runtime proof.
Only admit execution through the existing source-owning worker controls, with
fresh source checks and the exact task's native witnesses. Missing source,
mismatched CP identity, or unsupported relation is a **wall**, not permission
to invent a substitute task. This CP20–CP30 research history is not the
independent NIH/game checkpoint frontier in `systems/workspace/cp_motion.py`,
and it is not a universal gate over unrelated work.

## Reader-facing research naming and completion boundaries

Use **Finite Correspondence Research** for the investigation, **Finite Correspondence Process** for the bounded implementation, and **Correspondence Worker** only for an explicitly admitted worker role. Do not reuse retired product labels in prose, headings, user-facing summaries, or handoffs. The historical paths in links, scripts, manifests, code symbols, and archival records must remain unchanged for compatibility.

Describe an observed result only within its verified scope. Avoid promotional framing, launch language, or implying that a research checkpoint, working copy, or tested component is a finished product. A local PASS does not establish full integration, deployment, or production readiness.
