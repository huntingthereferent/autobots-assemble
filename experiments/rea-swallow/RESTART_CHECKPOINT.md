# Movement 12 — persisted investigation, process restart, and replay safety

Real REA version matcher from pinned MIT `morluto/rea@f0b9ef34c404c1c65f8167502db972b0bd708403`, reconstructed through prior verified Movements 8–11 and preserved by existing `ProcessWorkstation` as control and experimental source editions. The experiment adds a genuine REA TypeScript module `javascriptInvestigationCheckpoint.ts` (not an external imitation).

Each bounded REA investigation retains an on-disk checksum-checked snapshot including source/provenance, matched pair, both observation streams, pending source-derived request, accepted contexts, monotonic revision, and per-event content hashes. Writes are serialized using an exclusive lock, temp-file write plus fsync, atomic rename, and directory fsync. Duplicate event replay returns the prior committed state, conflicting replay IDs fail closed, completed witnesses cannot advance again, a corrupt snapshot is refused, and a stale exclusive lock **is not automatically stolen**.

In CI, a test spawns **different operating-system Node processes** for: initialize, construct request, capture left only, reload, resume while missing right, reject wrong input digest, capture right, accept verified difference, replay previous event, redundant advance, and checksum verification. It also checks no-change self-pairs, conflicting event IDs, an unrecovered lock, and corruption. No untrusted source execution in the REA library; the separate fixture CLI executes only the authored pure finite family in a timeout VM. The state is local to the same host filesystem, not replicated between GitHub runners or persisted by GitHub beyond uploaded test receipts.

Limits: A shared checksum detects accidental corruption but is **not authenticity or adversary-proof**, process restart is not the same as crash recovery from all possible power failures, and an unclean lock requires operator inspection. Native REA production does not yet call the module, nor is it an always-running background service or universal semantic verifier. Existing source, earlier experiments and `main` remain unchanged.
