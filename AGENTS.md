# Tracework agent operating instructions

## Working location and execution

This GitHub repository is the active Tracework workspace. Do not assume the project lives on the user's computer. Inspect the repository and its current branch, source, issues, workflow definitions, runs, logs, and recorded outputs before describing current state.

- **GitHub repository:** source, edits, commits, review, handoffs, and durable records.
- **GitHub Actions:** preferred available execution and verification surface for tests and automation. A workflow file or commit is not evidence that a run passed; inspect run status and logs when accessible.
- **GitHub Pages:** public read-only observation and proof-of-concept interface. It is not the entire Tracework product or a live representation of private processes.
- **Tracework:** developing finite-system environment. Do not conflate the public viewer, the implementation repository, and a future standalone application.
- **Local machines:** optional, only when specifically requested. An offline desktop is not a reason to stop GitHub work.

## How to proceed

When asked to continue (including `C` or `c`), resume the active repository task and make the next concrete, reviewable movement rather than restating a plan. When asked to audit, inspect actual source and evidence. When asked to run or verify, use the available GitHub execution path and report whether execution was observed.

Preserve the project's mathematical definitions, source identities, witness requirements, and historical evidence. Keep changes bounded and testable; avoid broad renaming or restructuring without an explicit need. Treat each research lane's claims as limited to its own witnessed results.

For language and profile edits, use [the canonical Language Referent description](LANGUAGE_REFERENT.md) and [evidence contract](LANGUAGE_REFERENT_CONTRACT.md): continuity as motion, finite witnesses that retain source relationships, and recursion under the same evidence conditions. Do not replace the three with a convenient shorthand, a fixed-container metaphor, or a universal proof claim. Audit the current source before editing; preserve historical quotations and scoped mathematical results as their own evidence.

Distinguish **committed**, **workflow triggered**, **running**, **passed**, **failed**, and **not verified**. Never imply an active worker or successful test merely because source code or a workflow exists. If a connector cannot start or read a run, state that specific limitation and continue with repository-supported work.

Use branch-based review for risky or broad changes. Do not expose private runtime journals, credentials, or data in public Pages or workflow artifacts. Keep logs and artifacts free of secrets.

## Presence and observation

"Presence" means following available real state and movement: source revisions, workflow events, actual logs, handoff ancestry, inputs, outputs, witnesses, and mismatches. Do not replace missing observation with inferred success or fabricated activity.

These instructions govern agent behavior in this repository; they are not a claim that all planned Tracework capabilities are implemented.
