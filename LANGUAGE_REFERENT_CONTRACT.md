## What the language referent is

**Name continuity:** "the language referent" and the earlier name "A/B" designate the **same referent** in James's account. The newer name is a communication choice for readers, not a new layer, replacement, or separate thing that later acquires mathematics. Mathematics is human formal language within the continuing investigation. The finite models remain scoped representations with their own proof obligations. See the [research account](https://github.com/huntingthereferent/huntingthereferent) for the current public research record.

The language referent is **language for recognizing, describing, and continuing relationships in movement**. The referent is the relationship through the step; it is not itself a theorem, equation, notation system, or a specific mathematical operation. See [Language Referent](LANGUAGE_REFERENT.md) for the current account, [the October 13 grounding note](LANGUAGE_REFERENT_GROUND_2026-10-13.md) for the naming and regrounding corrections, and [the October 11 historical record](AB_Ground_Record_Current_Note_2026-10-11.md) for the earlier physical two-step hypothesis.

Mathematics is a human formal language. Particular generators formally labeled A and B, inverse constructions, and correspondence proofs in this repository are **formal mathematical representations** of specified relations, with their own state spaces, assumptions, witnesses, and scope. Do not mistake a result proved for a particular finite transformation family for a definition or universal proof of the language referent.

This repository does **not** redefine the language referent as a workflow engine, project manager, policy engine, state machine, job tracker, filesystem layout, or AI prompt.

## Using the language referent in repository operations

Operational layers must respect these invariants:

1. **Current referent is primary.** Older layers are evidence only when the current relation actually reaches them.
2. **Movement requires a witness/evidence contract.** A relation is not admitted merely because it is convenient or plausible.
3. **Outputs remain admissible inputs.** A completed movement can be presented to the same contract on the next pass without changing the meaning of the contract.
4. **Walls are explicit.** Missing evidence, missing authority, inaccessible tools, unresolved correspondence, or incompatible contracts produce a wall rather than a fabricated bridge.
5. **UNKNOWN/PARTIAL are preserved.** Lack of evidence is not evidence of absence, and coverage is not automatically preservation.
6. **Provenance survives movement.** Source, witness, parent relation(s), and the reason for movement remain recoverable.
7. **No silent reorientation.** An implementation detail, old experiment, or prior conclusion cannot replace the current referent unless a supported movement reaches it.
8. **Another side, same referent.** A blocked relationship may be inspected from another vantage; this does not license a new referent or bypass the witness conditions.

## Recursion test

A protocol is structurally acceptable only if its output can be used as input to another run of the same protocol shape without inventing a new evidence standard.

That is the practical closure test used throughout this repository.
