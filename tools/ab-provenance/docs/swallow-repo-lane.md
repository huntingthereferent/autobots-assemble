# Workstation lane: Swallow Repo

**Operational meaning for James: fix or reground the referent.**

The work is not to copy, imitate, relabel, or cosmetically reproduce another
repository. The work is to follow actual source relationships, determine
where they drift, correct them through tested source editions, and carry
forward whatever survives native observation.

## Movement

1. Identify the original repository and exact source owner/commit.
2. Inspect its actual implementation and identify a bounded useful operation.
3. Reground the relationship through the existing ProcessWorkstation's
   original source copies, revisions, and evidence records.
4. Execute source-owned native tests and independent A/B contracts. Preserve
   failures and boundaries without manufacturing an equivalence claim.
5. Carry forward source ancestry, evidence, uncertainty, invalidations,
   and the next observation; visual provenance is only an inspection surface.
6. Produce a **release-quality A/B tool** with real commands, packaging,
   documentation, tests and provenance, all under A/B's own license.

## Source rights

A/B original code, interface and documentation remain under the repository's
All Rights Reserved product license. The source referent's original license
is neither copied onto A/B nor silently canceled. The pinned REA upstream
submodule retains its MIT license and original copyright. REA source is not
bundled in the A/B product wheel or release candidate.

## Current capability boundary

The current real adapter can reground and verify five source stages in
pinned REA JavaScript matching/investigation. The reusable lane name does
not mean that arbitrary GitHub repositories are automatically supported.
Each new source requires its own grounded adapter and native verification.

The output gate requires a PASS receipt and authentic source hash-matching
logs. The ship command builds an offline **release candidate**, not a
published public release. The documentation must say what remains incomplete.

## Repeatability check

The original referent is tested **before and after** A/B's source correction.
The same original native REA tests must retain their exact assertion
identities and outcomes, while the actual original REA source file changes.
The resulting release explicitly reports what still differs: complete REA
CLI/MCP and provider coverage is NOT reconstructed. Identical aesthetics
or copied docs cannot count as a successful result.
